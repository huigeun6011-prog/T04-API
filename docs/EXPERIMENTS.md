# 시도·실험 기록

시도한 방법과 결과를 성공·부분 개선·효과 없음·철회를 가리지 않고 남긴다. 새 시도는 아래 형식으로 **색인 표와 상세에 함께 추가**한다. 실패 원인을 처음 정리한 초기 기록은 [FAILURES](FAILURES.md), 가정은 [ASSUMPTIONS](ASSUMPTIONS.md), 결정은 [DECISIONS](DECISIONS.md), 현재 상태와 다음 후보는 [ROADMAP](../ROADMAP.md)에 있다.

**표기 원칙**
- `사용자 진술`은 사용자가 기억을 말해 준 내용이고 코드·자료로 확인하지 못했다.
- `기록 없음`은 이유나 결과가 어디에도 남아 있지 않다는 뜻이다. 추정으로 채우지 않았다.
- 피크 19사례는 모든 실험에서 진단·사후 보고에만 썼고 학습·튜닝에 쓰지 않았다.
- 수치는 해당 보고서 기준이다. 추정 라벨 지표는 실제 승객 정확도가 아니다.

**상태 정의:** 채택(production에 쓰임) / 부분 개선 / 효과 없음 / 악화 / 진단 / 철회 / 반영

## 상세

### E-01 승하차 균등 분배 첫 구현
- **무엇을:** 시간대별 승차인원을 각 열차에 균등하게 나눠 종점 재차를 확인했다.
- **결과:** 종점 재차 상행 평균 +26.81(절대평균 35.06), 하행 평균 −23.76(절대평균 42.75).
- **원인:** 상하행을 구분하지 않고 일괄 1/n을 나눠 비현실적이었다.
- **배운 점:** 방향 몫이 필요하다. 이후 모든 방법은 방향 몫(p, q)을 변수로 둔다. 단 같은 방향 열차끼리의 균등 분배는 계속 남았다([A-002](ASSUMPTIONS.md)).
- **증거:** [F-001](FAILURES.md), 커밋 `5b3bd55`(미완성 표기), `54e26c5`.

### E-02 기존 연구 방법 조사
- **결과:** Fluid Analogy Method는 계산식이 공개되지 않았고 양방향에 적용하기 어렵다. OD 행렬 추정 논문은 시간대 정보를 무시하고 실측 검증이 없다.
- **판단:** 손실함수와 제약조건을 직접 설정하는 방향으로 갔다([F-002](FAILURES.md)).

### E-03 PyTorch 열차 재차 예측 모델
- **무엇을:** 신경망으로 열차 재차를 예측하는 모델(`train_load_model.py`, `outputs/best_model.pt`).
- **결과:** 학습이 너무 느렸다. 방법론을 찾아보니 HistGradientBoosting이 더 빠르고 적절하다고 판단해 교체했다. **사용자 진술**이고 속도나 정확도의 비교 측정은 기록 없음.
- **현재:** 이 파일들은 이전 경로이며 현재 공식 모델과 혼용하지 않는다.

### E-04 12일 자료 학습
- **무엇을:** 12일·61,788행으로 만든 예전 모델·CSV.
- **이유:** 속도가 느리다고 해서 일수를 줄였다고 사용자가 기억한다. 왜 하필 12일인지는 **기록 없음**이고 사용자도 모른다.
- **후속:** 2026-11-16에 전체 731일·3,733,691행으로 재생성했다. 기존 자료는 `outputs/backup_before_rebuild_20261116_124052/`에 보관했고 24시 날씨 수정 전 자료라 대안으로 쓰지 않는다.

### E-05 버스 노선 추가
- **무엇을:** 지하철만으로는 갈 수 있는 범위가 좁아 버스 노선을 추가하려 했다. 커밋 `a15775e`("철회 가능성 있음"), `dbe77cb`(버스 시간표·차량 추적 알고리즘)로 시도했다.
- **철회 이유(사용자 진술):** 버스의 한산함을 알려면 노선마다 지하철과 같은 재차 예측을 해야 하는데, 버스는 환승까지 있어 유의미한 수준으로 전부 예측하기 어렵다.
- **결과:** 지하철 1호선에 한정. 버스 관련 파일은 이후 커밋에서 삭제됐다.

### E-06 결과 확인용 스크립트·옛 최적화기
- **파일:** `scripts/analysis/`의 `fast_optimizer.py`, `vectorized_optimizer.py`, `test_optimization.py`(scipy `minimize` 사용), `train_load_simulation.py`, `occupancy_check.py`, `time_check.py`, `time_omit_check.py`, 그리고 `outputs/reboarding_estimate_2025-11-02~04.json`, `outputs/train_load_2025-11-04.json`.
- **알려진 것:** 사용자는 생성물이 적합한지 눈으로 확인하는 코드들이었을 것이라고 기억한다(**사용자 진술**). 코드로 확인되는 것은 다음뿐이다.
  - `occupancy_check.py`: 역별 시간 승차·하차와 열차 수로 열차당 승차 추정(`boarding_per_train`)을 계산해 `reboarding_estimate_{날짜}.json`으로 저장(기본 날짜 2025-11-04). 2025-11-01 파일은 커밋 `54e26c5`에서 삭제됨.
  - `train_load_simulation.py`: 이 추정 파일을 읽어 `outputs/train_load_2025-11-04.json`을 만든다(코드 경로 기준).
  - `time_check.py`, `time_omit_check.py`: 시간표 CSV와 JSON의 시각 개수·누락을 대조한다(코드 첫머리 기준).
- **확인하지 못한 것:** 사용자가 기억하는 "종점 재차인원을 계산해 보여주는" 부분이 위 어느 파일인지, `fast_optimizer`·`vectorized_optimizer`·`test_optimization`의 용도·순서·결과. **기록 없음**.

### E-07 시간표 보정
- **무엇을:** 2026-03-30 개편으로 API 자료가 실제 운행과 달라져(F-003), 공식 홈페이지 평일표로 20260330 시간표를 만들고 이전/이후를 분리했다. 250930 표는 누락 추정 시각(정부청사 24:01, 갈마 24:03, 월평 24:05, 갑천 24:07)을 추가했다([A-001](ASSUMPTIONS.md)).

- **한계:** 1~4분 인접역 연결과 종착역 보간 가정은 남는다. 실운행 입증은 아니다. 축제 등 비정규 운행일 제외(F-003 개선안 3)는 **미실행**.

### E-08 200회 solver + clamp·종점 0 덮어쓰기 (production)
- **무엇을:** 역·시간별 방향 몫 p, q(하루 800개)를 Adam 200회로 최적화하고, 음수 재차는 순차 clamp, 종점은 0으로 덮어써 라벨을 만들었다. 이 라벨로 HGB를 학습해 `outputs/load_predictor.joblib`이 production이다.
- **결과:** 날짜 holdout MAE 20.14, R² 0.877(추정 라벨 재현성). 감사에서 보존식이 187,731행에서 깨졌고(허용 0.015명), 종점 0 덮어쓰기 전 양수 잔여가 93,943열차(최대 380.66명), 비종점 clamp가 17,006행이었다.
- **해석:** 저장된 load가 비음수·종점 0인 것은 후처리 결과이지 물리 제약을 만족시켰다는 뜻이 아니다.
- **증거:** `outputs/diagnostics/gt_solver_before_improvement.py`, [gt_improvement_report](../outputs/diagnostics/gt_improvement_report.md).

### E-09 수렴 진단
- **무엇을:** 대표 6일 × 200/500/1000회 × 초기값 2종.
- **결과:** 200→1000회에서 손실이 4.47~14.17% 줄었지만 종점·음수 위반은 남았다.
- **배운 점:** 반복 횟수만 늘려서는 해결되지 않는다.
- **증거:** `outputs/diagnostics/gt_convergence.json`.

### E-10 배분 개선 후보
- **무엇을:** 불가능한 방향으로 배분되어 사라지던 인원을 가능한 방향으로 정규화, 양쪽 모두 불가능하면 slack, 최대 1000회, `raw_load`·`load`·`load_correction` 분리, 종점 0 덮어쓰기 제거.
- **결과:** raw 보존식 위반 0, 배분+slack=원본 확인. 그러나 원시 음수 105,609행(최소 −775.31), 종점 잔여 |p95| 44.88·최대 3,127.19. holdout MAE 21.94, R² 0.859(라벨 정의가 달라 production과 단순 비교 불가). 실제 피크 모델 MAE 374.45(production 375.99).
- **판단:** 실제 정확도 개선이 확보되지 않아 production에 적용하지 않았다. **보존식이 맞는 것과 물리적으로 타당한 인원이 나오는 것은 다르다.**
- **증거:** [gt_improvement_report](../outputs/diagnostics/gt_improvement_report.md), `candidate_training/`.

### E-11 3가정 ablation
- **무엇을:** 시간 Huber 정규화, 요일 partial pooling, 승차 headway를 옵션으로 구현하고 같은 6일 × 5방법 × 2초기값 × 1000회(총 60회)로 비교.
- **결과(정상 5일 평균 종점 MSE):** 기본 539.62 / 시간 541.72 / pooling 541.91 / headway 1107.80 / 전부 1147.53. 음수 MSE 기본 12.14 → 전부 53.10. 시간 정규화는 인접 변화량 26.3%, pooling은 template 거리 45.3% 감소. 전부 적용은 평일 3일 악화·토요일 2일 개선.
- **해석:** 부드러움·패턴 일치는 좋아졌으나 물리 잔차 개선이 아니다. 자정 이후 운행 가능일의 개선은 slack 증가로 설명된다.
- **판단:** 기본 활성화·전체 재학습·production 교체를 하지 않았다.
- **증거:** [assumption_ablation/report](../outputs/diagnostics/assumption_ablation/report.md).

### E-12 격차 진단(실현 가능성 상한)
- **질문:** 실제 피크 열차(604~717명)와 추정 라벨(실제의 0.42~0.61배, 평균 0.53)의 약 350명 격차가 승하차 자료 때문인가, 배분 방식 때문인가.

### E-14 자료 기반 방향 prior(중력 + 소프트 KL / IPF)

### E-15 연속 도착률 곡선 + headway 악화 원인 진단
- **무엇을:** 한 시간 안의 도착이 균일하다는 가정 대신, 시간별 합계를 정확히 보존하는 부드러운 1분 단위 도착률 곡선(1차·2차 차분 최소화)을 만들어 headway 승차 배분에 넣었다(`gt_arrival_curve.py`). 권종 자료는 쓰지 않았다. 동시에 균일 headway가 왜 피크 추정을 낮췄는지 진단했다. 5개 설정(기본, 균일 headway, d1, d2, d2 혼합) × 6일 × 2시드.
- **진단 결과(원인):** 질량은 보존된다(슬랙은 승차의 약 0.07%, 대부분 막차 이후 도착). 시간 경계에서 각 시간 승차의 7~15%가 다음 시간 첫 열차로 넘어간다. 핵심은 승차는 열차별 간격에 비례해 달라지지만 **하차는 열차당 균일**하다는 비대칭이다. 같은 p, q로 평일 종점 MSE가 5~8배 커진다(예: 473 → 3,769). 최적화는 이를 줄이려고 부하 규모를 약 30% 낮춘다(평균 load 129.6 → 91.2). 이 마지막 인과는 추정이고 별도 ablation(headway식 하차)은 하지 않았다. 기존 `boarding_exposures`에서 버그는 찾지 못했다.
- **결과(정상 5일 평균):** 종점 MSE 기본 539.8 / 균일 headway 1108.2 / 곡선 d1 559.8 / d2 600.4 / 혼합 703.9. 피크 19건 추정/실제 평균 0.512 / 0.299 / 0.385 / 0.369 / 0.359, MAE 325 / 465 / 409 / 420 / 426. 곡선은 균일 headway가 낮춘 피크 추정의 약 3분의 1을 회복하지만 기본보다는 모두 나쁘다. 자정 이후 운행일의 오차 감소는 slack(약 4,400) 때문.
- **알게 된 것:** 아침 피크 상위 5개 역의 8시 구간 마지막 20분 비중이 0.33(균일 0.333)으로 곡선이 거의 평평했다. 7시·9시 물량이 비슷하고 8시가 단일 봉우리라 시간 합계만으로는 시간 내 모양이 안 나온다.
- **시사점:** headway 계열의 문제는 도착 모양이 아니라 승차와 하차의 열차 단위 비대칭이다. 이를 직접 푸는 후보는 열차 단위 OD 변수(보존식을 구조로 보장)다.
- **증거:** [arrival_curve/report](../outputs/diagnostics/arrival_curve/report.md), `scripts/data_prep/gt_arrival_curve.py`, `diagnose_headway_mass.py`, `diagnose_headway_transplant.py`.

### E-16 열차 단위 OD 변수(하드 보존식)
- **무엇을:** 열차마다 "정거장 a에서 타서 b에서 내린 인원" x[k,a,b]≥0을 변수로 둔다(평일 약 5.5만 개). 재차인원은 x의 합이라 보존식·종점 0·비음수가 구조로 성립하고 p/q 변수가 없다. 시간별 승하차 합계는 소프트 제약(오차²/(관측+10))과 KL 정규화(λ)로 맞춘다. 합계가 맞지 않는 칸은 명시적 slack. 설정은 실행 전 고정: 균일 기준 2, headway 가중 2, 중력 기준 8(β 2종 × γ 2종 × λ 2종), 비교 기준은 기존 방식. 풀이는 L-BFGS-B(하루·설정당 70~330초, 기존 11초). 비교 점수 TNV(합계 불일치 + 물리 위반)를 미리 정의.
- **결과(정상 5일 평균):** 물리 위반이 기존 2.8%에서 0. 합계 불일치는 0.6~2.4%(λ=0.01이 더 잘 맞음). 기존의 합계 불일치는 0.007%이고 대신 오차가 종점·음수 잔차에 있다. 균일 OD의 load 중앙/p95/p99 125/291/363으로 기존(131/297/355)과 비슷해 headway 때 생겼던 부하 붕괴가 없다. 기존과의 순위 상관(Spearman) 0.94.
- **피크 19건 사후 비교(1회, 보고만):** 추정/실제 평균 기본 0.512, 균일 OD 0.618(MAE 254), headway 가중 OD 0.624(MAE 249). 중력 감쇠 기준은 0.37~0.54로 오히려 낮아지고 감쇠가 클수록 낮다. headway 가중은 균일에 거의 더하는 것이 없다. 어떤 설정도 어떤 사례에서도 0.75를 넘지 않는다.
- **해석:** 구조 변경이 피크 추정을 처음으로 올렸지만(0.51 → 0.62) 실제의 0.62배로 격차는 남는다. 수준은 사실상 이동 거리 prior에 좌우된다(균일 기준은 장거리 비중이 크고 감쇠 기준은 짧은 이동이 많아 중간 구간 load가 낮아짐). 1정거장 감쇠 γ=0.3은 같은 β에서 추정을 약간 올렸다(0.504 → 0.543, 0.372 → 0.412).
- **주의:** 합계 불일치를 소프트 제약이 흡수하므로 TNV가 좋은 것은 부분적으로 허용 오차 덕분이다. 최적화는 ftol에서 멈춰 준수렴이다(투영 기울기 0.13~1.7). OD 설정은 결정적이라 시드 민감도를 보지 않았다. 731일 전체를 다시 만들면 하루 70~330초 × 731일이라 계산 비용이 크다(병렬이 필요).
- **증거:** [train_od/report](../outputs/diagnostics/train_od/report.md), `scripts/data_prep/gt_train_od.py`, `experiment_train_od.py`, `validate_train_od_peaks.py`.

- **한계:** 대부분의 적합이 반복 한도에 도달해 수렴하지 않았다(E1 잡음 2%는 정보량뿐 아니라 풀이기와 예산의 한계이기도 함). 하루, 잡음 시드 하나, 계수 시드 하나. 실제 태그 잡음, 개찰구와 승강장 시간차는 반영하지 않았다. E2는 π를 열차별 자유로 두어 설계상 w를 흡수하기 쉬운 구성이다.
- **검증하지 않은 가설:** w를 저차원(시간대 기저 4~6개 등)으로 제한하고 부드러움 정규화를 두는 방식은 시험하지 않았다. 0단계의 큰 특이값 방향이 이를 시사하지만 가설이다.

- 사용자가 하지 않기로 한 것: 권종 자료 활용, 베이지안(불확실성) 분해(이유 기록 없음, [D-008](DECISIONS.md)), 대전 추가 혼잡도 자료 탐색(실측 자료는 평가용이지 학습용이 아니라는 판단, [D-007](DECISIONS.md)).
- 실제 재차인원의 출발 전/후 측정 시점 확인, 다른 지역 자료 검증은 처음에 하지 않기로 했다가 2026-11-17에 하기로 바꿨다(합성 자료 실험을 먼저).
