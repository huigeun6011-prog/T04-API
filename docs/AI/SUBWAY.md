# 대전교통공사 승하차 자료 수집

## 현재 수집 코드

`scripts/utils/collect_data.py`는 공공데이터포털의 대전교통공사 `getTicketTypeTraffic01` API를 일자별로 호출합니다.

- API 키는 프로젝트 루트 `.env`의 `SUBWAY_API_KEY`에서 `python-dotenv`로 읽습니다.
- 요청은 `startDate`와 `endDate`를 같은 날로 설정하고, 페이지당 100행을 요청합니다.
- 다음 페이지는 응답의 `totalCount`까지 순차 요청하며 페이지 사이에 0.3초, 날짜 사이에 0.5초 대기합니다.
- 날짜별 결과는 `data/raw/subway/YYYY-MM-DD.xml`에 저장합니다.
- 기존 파일이 있으면 건너뛰도록 `skip_existing = True`로 되어 있습니다.

## 원본 보존에 관한 주의

API 응답은 페이지 단위입니다. 현재 코드에서는 첫 페이지 XML을 기준으로 다음 페이지의 `<item>`들을 합쳐 **하루 단위 XML 하나**로 저장합니다. 따라서 다중 페이지 날짜의 저장 파일은 단일 HTTP 응답 원문이 아니라 페이지들을 합친 XML입니다. 이 동작은 “응답 원본을 가공하지 않고 그대로 보존”하려는 이전 수집 메모와 다릅니다. 페이지별 원본 보존이 필요하다면 코드와 저장 규칙을 별도로 바꿔야 합니다.

## 자료 변환 흐름

수집 XML을 `scripts/data_prep/`의 처리 스크립트가 역별 승차·하차 JSON으로 정리합니다. 모델에서 사용하는 결과 경로는 `data/processed/subway/{날짜}.json`이며, 한 레코드에 역별 `boardings`와 `alightings`가 들어갑니다. 열차 운행일의 24시 버킷은 익일 0시 자료를 포함하도록 모델 생성 코드에서 처리합니다. 01~04시 자료 처리와 00시 귀속은 [결정 기록](../DECISIONS.md)에 적힌 판단을 따릅니다.

## 코드 기본 기간과 현재 파일 범위

`collect_data.py`에 지정된 기본 수집 기간은 **2024-11-01~2025-10-31**입니다. 현재 `data/raw/subway/`에는 더 뒤 날짜의 파일도 있어, 저장소 전체가 현재 스크립트의 한 번 실행으로 만들어졌다고 볼 수는 없습니다. 파일명 기준으로 확인된 자료 범위는 2024-11-01부터 2026-11-02까지이며, `2026-11-02_refetched.xml`처럼 재수집 흔적이 있는 파일도 있습니다.

수집 날짜를 변경하려면 스크립트의 `start_date`와 `end_date`를 검토합니다. 실패 로그는 현재 콘솔에 출력되며, 별도의 `failures.md` 파일로 자동 기록되지는 않습니다.
