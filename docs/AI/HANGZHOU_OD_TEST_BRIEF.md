# 항저우 C선: 열차별 정답 재차인원과 OD 역산 민감도 시험 (방향 메모, 미실행)

작성 2026-11-18. **상태 갱신(2026-11-18): 첫 실행을 마쳤다(평일 3일, 시간 해상도 1시간, 데이터 추정 랙). 결과는 [report](../../outputs/hangzhou/od_test/report.md)와 [EXPERIMENTS](../EXPERIMENTS.md) E-34, 기준은 `outputs/hangzhou/od_test/criteria.md`. Adam 비교는 이어서 했다(E-35). 주말·05~07시는 하지 않았다.** 아래는 실행 전에 쓴 방향 메모이다.

(원문) 상태: 설계 방향만 적은 메모이며 아직 실행하지 않았다. 이 작업은 항저우 시간표 복원을 하던 세션과 **별도의 에이전트**가 맡는다. 시작 전에 사용자 승인이 필요하다(새 실험이고 대전용 OD 코드를 C선 구조로 옮기는 규모가 큰 작업이다). 배경은 [HANGZHOU_TIMETABLE_BRIEF](HANGZHOU_TIMETABLE_BRIEF.md), [EXPERIMENTS](../EXPERIMENTS.md)의 E-22~E-33, [HANDOFF](../HANDOFF.md) §11이다.

## 1. 왜 하는가 (목적을 낮춘 이유 포함)

- 대전에는 열차별 실제 재차 정답이 거의 없어(피크 19건, 검증 전용 D-007) OD 역산 결과가 맞는지 직접 확인할 수 없다. 다른 지역에서 정답을 구해 대전 결과를 입증하는 것도 불가능하다(q는 도시마다 다르다, E-17: 합계만으로는 열차별 값이 식별되지 않고 결과는 기준 분포 q에 좌우된다).
- 그래서 목표를 **"방법이 정답을 얼마나 복원하는가, 기준 분포 q가 틀리면 얼마나 틀어지는가(민감도), 순위와 수준 중 무엇을 믿을 수 있는가"**로 낮춘다. 이 결과는 대전 결과에 "수준은 믿지 말고 순위만 쓴다", "q가 이만큼 틀리면 이만큼 틀릴 수 있다" 같은 **한계 표시를 붙이는 근거**로만 쓴다. 대전 결과가 맞다는 증명이 아니다.
- 항저우 C선만 쓴다. 이 시험에서 얻은 q나 계수를 대전에 그대로 옮기지 않는다.

## 3. 정답 재차인원 만들기

- 직접 통행 승객(입장·출장이 모두 C 태그, 같은 날, 입장→출장 시차 0~180분)을 열차에 배정한다. 배정은 `lineC_direct_check`와 같은 방식을 기본으로 한다. 출장 태그 시각에서 역별 랙을 뺀 시각 이전에 출장 역에 도착한 가장 가까운 선행 열차를 고르고, 그 열차의 입장 역 출발이 입장 태그 이후여야 한다.
- 열차 k, 구간 i의 정답 재차 = 그 열차에 배정된 승객 중 승차 역 ≤ i < 하차 역인 인원.
- 이 정답은 **추정 시간표 위의 정답**이다. 배정 노이즈(경계 승객이 앞뒤 열차로 갈림)가 정답 노이즈다. 랙을 ±(예: 30초) 바꾼 정답 몇 종으로 정답 자체의 불확실성도 같이 재라.
- 환승 승객(C 하차의 약 36%)은 정답과 역산 입력 양쪽에서 모두 제외해, 같은 승객 집합에서 만든다. 대전은 단일 노선이라 환승이 없으므로 이쪽이 대전 구조와 더 닮았다(대전 쪽 환승 부재는 문서 기준이며 별도로 확인한 것은 아니다). 단, 환승 승객이 빠지면 이동 거리 분포가 짧은 쪽으로 치우친다(선택 편향). 결과 해석에 이를 명시한다.
- 배정 불가·음수 대기 승객 처리 규칙, `imputed` 열차와 `low_signal` 열차의 처리(정답·평가에 포함할지)는 **실행 전에 criteria 파일에 고정**한다.

## 4. 역산 입력과 방법

- 같은 승객 집합에서 **역×시간대별 승차·하차 합계만** 뽑아 역산에 넣는다. 열차 정보는 시간표(최종 시간표)만 쓴다. 정답 재차는 보지 않는다.
- 먼저 **대전과 같은 목적함수·설정**(균일 q, λ=0.01, 소프트 합계, KL)으로 변경 없이 돌린다. 시간 해상도(1시간 단위 등)는 대전 정의를 따르는 것을 기본으로 하고, 다르게 하면 이유를 적는다.
- Adam 기반 기존 GT 방식도 같은 입력에서 가능하면 비교한다.

## 5. 시험 설계 (모두 사전 고정)

1. **기본 복원:** 정답 대비 열차별 재차의 순위 상관(시간대 안, 전체), 수준 비율(추정 평균/정답 평균), 피크 열차 재현, 구간별 오차. 평일 여러 날(처음에는 3일 정도, 계산 시간을 보고 확장).
2. **q 민감도:** 실제 q(정답 OD에서 계산한 이동 거리 분포), 균일 q, 중력 감쇠(β, γ 격자), 의도적으로 왜곡한 q. λ 격자. 어느 q에서 순위와 수준이 얼마나 변하는지가 핵심 산출이다.
3. **입력 잡음:** 승차·하차 합계에 0/2/5% 잡음.
4. **대조:** 정답을 무작위로 섞은 열차에 대한 지표(우연 수준), 같은 입력의 Adam 기준.
5. **하위 집단:** 시간대(혼잡/낮/저녁), 방향, 분석 구간 안/밖.

## 6. 보고할 것

- 순위는 믿을 만한가, 수준은 믿을 만한가를 구분해서. q가 틀릴 때의 오차 범위.
- 어느 시간대·방향·구간에서 믿을 만한가. 정답 자체의 불확실성(랙 ±)과 비교.
- 이 결과를 대전 한계 표시에 어떻게 옮길 수 있는지(그리고 옮길 수 없는 것).

## 7. 지켜야 할 것

- 대전 production 모델, GT, `outputs/load_predictor.joblib`, `scripts/data_prep/`의 원본을 수정하지 않는다. 대전 q를 이 시험 결과로 정하지 않는다. 대전 피크 19건은 검증 전용이다(D-007).
- 사전 기준을 실행 전에 `criteria.md`로 고정하고 결과를 본 뒤 바꾸지 않는다. 결과가 나빠도 그대로 보고한다.
- 정답이 태그와 복원 시간표에서 나온다는 순환·배정 노이즈 한계를 결과에 항상 같이 적는다. 항저우 C선, 환승 제외, 추정 시간표 위에서만 말할 수 있다.
- 하위 에이전트는 `report.md` 쓰기가 거부된 적이 있다. 거부되면 우회하지 말고 본문을 보고에 담는다.
- 원본 데이터(`data/external/`)는 수정하지 않는다. 큰 CSV는 하루씩 읽고 캐시(`outputs/hangzhou/cache/`, gitignore)한다.
