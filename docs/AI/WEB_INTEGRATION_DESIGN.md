# 웹·예측 API 연결

기준일: 2026-11-23. 2026-11-23의 D-028 개편(상대 순위만 표시)이 반영되어 있고, 이 개편은 브라우저에서 눈으로 확인하지 않았다. 이 문서는 현재 `web/`과 `prediction_api.py` 코드를 설명한다. API 연결이 된다는 사실은 추천 순위나 혼잡 예측이 실제와 맞는다는 뜻이 아니다.

## 구성과 데이터 흐름

1. `scripts/build_web_poi.py`가 통합 POI 자료를 `web/data/pois.json`으로 만든다. 현재 파일에는 548곳이 있고, 532곳에 좌표가 있다. 좌표 없는 11곳은 산책로 자료다.
2. 브라우저는 `web/index.html`, `app.js`, `analysis.js`, `layout.js`, `weather-client.js`를 사용한다. 지도 SDK는 `kakao-loader.js`가 `config.local.js`의 브라우저용 Kakao 키로 불러온다. 키는 서버 응답이나 문서에 넣지 않는다.
3. 브라우저는 출발 좌표, 날짜, 시간 범위, 장소 종류, 선택적 도보 한도를 `POST /api/recommend`로 보낸다.
4. `prediction_api.py`가 `outputs/load_predictor.joblib`, 날짜별 시간표, 날씨 자료와 POI 좌표를 사용해 이동 후보를 계산한다. 모델은 브라우저에서 실행하지 않는다.
5. 서버 응답의 장소·순위 자료를 목록, 지도 경로, 시간대 순위, 히트맵에 쓴다. `/api/profile`은 제거했고 `web/data/station_profile.json`은 남아 있으나 웹이 쓰지 않는다.

## 데이터와 API

`prediction_api.py`는 Python 표준 `ThreadingHTTPServer`로 웹 정적 파일과 API를 기본 포트 5500에서 함께 제공한다. 브라우저는 같은 출처의 상대 경로를 사용한다. 정적 파일은 `web/` 안에서만 GET/HEAD로 제공하며 `.env`, `outputs/`, 원본 `data/`는 공개하지 않는다. 다른 API 프레임워크를 사용하지 않는다.

| 경로 | 동작 |
|---|---|
| `GET /api/health` | 모델 로딩 가능 여부 |
| `GET /api/stations` | 앱의 역 좌표 22개 반환 |
| `GET /api/predict?date=&hour=&station=&direction=` | 단일 역·시간 예측(`predicted_load`). 달력의 00시는 전날 운행일 24시로 변환. 웹은 쓰지 않음 |
| `POST /api/recommend` | 시간표로 이동 가능한 장소 후보를 만들고 거리 순으로 그룹화하며 구간별 시간대 순위를 붙임 |

추천 요청의 시간 범위는 운행일 기준 05~24시다. `max_walk_minutes`는 선택값(1~240분)이고 생략하면 제한이 없다. 한산함 비중(`quiet_weight`)과 `matrix`는 D-028로 제거했다. 응답 후보는 `rank`(정수 1..N, 같은 구간의 고른 시간 범위 안 순위, 1이 가장 한산, 값이 같으면 이른 시간 먼저), `rank_n`, `hour_ranks`(시간대별 `hour`·`rank`·`total_minutes`·`trains`), `alt_times`(`hour`·`rank`·`total_minutes`)를 담고, `mean_load` 같은 인원 수치는 웹 응답에 없다. `meta`에 `rank_basis`·`tie_rule`·`limitations`가 있다. 비교 규칙은 순위 차 2 이하이면 같은 혼잡 수준, 3 이상이면 숫자가 작은 쪽이 더 한산하다.

`POST /api/recommend`는 출발지에서 가장 가까운 역, POI에서 가장 가까운 역, 시간표상 운행 가능한 열차와 열차 이용 구간의 예상 재차인원을 결합한다. 직접 걷기 시간은 직선거리 × 1.3 ÷ 4.5km/h로 어림한다. 열차 ETA에는 승차역까지·하차역에서의 도보와 열차 운행시간만 넣고, 대기·환승은 포함하지 않는다.

후보는 총 추정시간 30분 이하(`near`)와 초과(`far`)로 나뉜다. 각 그룹은 직선거리·장소 이름 등으로 정렬하며 혼잡도로 정렬하지 않는다. 시간대의 값은 그 시간 열차들의 예상 재차 평균이고 가장 한산한 열차 한 대를 고르지 않는다. 도보 전용 후보에는 순위가 없다(`rank` null). 동일 장소는 한 후보만 결과에 남기고 다른 열차 시간 최대 3개를 `alt_times`로 붙인다. 그룹별 도보 후보는 결과 상한의 1/3까지 먼저 담는다. 이는 현재 코드의 정책이며 실제 추천 효용이 검증된 기준은 아니다.

날씨는 브라우저 `weather-client.js`와 서버가 각각 조회한다. Open-Meteo는 API 키 없이 호출한다. 브라우저 클라이언트는 500ms 지연 합치기, 중복 요청 합치기, 최소 10초 간격, 예보 1시간·과거 자료 7일 캐시를 사용한다. 24시 구간은 다음 날짜 00시 날씨를 사용한다. 서버는 로컬 날짜별 자료를 우선 사용하고 필요하면 Open-Meteo를 조회한다.

## 지도와 역 좌표

현재 역 좌표 22개는 사용자가 지도에서 짚어 전달한 WGS84 위도·경도다. 기준 표는 [STATION_COORDINATES.md](STATION_COORDINATES.md)에 있다. `web/app.js`의 `STATIONS`가 브라우저 마커, 출발지 역 선택, 가까운 역 계산에 쓰인다. `prediction_api.py`는 시작할 때 이 배열을 읽어 서버 메모리에 보관하므로 좌표를 바꾼 뒤에는 서버도 재시작해야 추천 계산에 새 좌표가 반영된다.

지하철 경로 곡선은 `web/data/metro_line_geometry.json`의 OpenStreetMap 대전 1호선 양방향 관계 7792527·7237829를 바탕으로 한다. 22개 역 사이 42개 방향별 구간을 저장하며, OSM 역점과 사용자가 제공한 역 좌표의 차이를 각 구간을 따라 보간해 선로 끝점이 역 마커에 닿게 한다. OSM은 공식 측량 자료가 아니며, 출처가 다른 좌표를 이어 만든 경로 보정이다. 자료를 못 불러오면 앱은 역 좌표 사이 직선으로 대체한다. 지도 경로 카드에는 OpenStreetMap 출처·저작권 링크가 표시된다.

## 화면 동작

- 검색 문장에서 출발지, 날짜, 시간대, 장소 종류, 걷는 시간 합계 한도를 입력한다. 출발지는 지도에서 찍거나 역 목록에서 고른다.
- 거리는 출발지에서 장소까지의 직선거리다. 운영시간과 실제 보행 경로는 제공하지 않는다. 장소 방문객 수를 예측하지 않는다.
- 추천 카드는 출발·도착역, 출발 시각, 도보 추정, 열차 이용시간, 총 추정시간과 시간대 순위를 보여 준다. 재차인원 수치는 보이지 않으며 `no_train` 도보 전용 후보에는 순위가 없다.
- 결과는 가까운 곳·지하철로 멀리 탭으로 나뉜다. 지도에는 선택한 장소 핀과 선택 경로가 표시된다. 카카오맵 길찾기는 외부 링크로 넘기며 앱 안에서 보행·대중교통 경로를 계산하지 않는다.
- 시간대 순위는 응답의 `hour_ranks`를 쓴다. 시간대를 눌러도 서버를 다시 호출하지 않으며, 선택한 시간대는 그 시간 열차들의 출발 시각을 시간순으로 보여 준다. '더 나은 시간' 안내와 인접 시간 목록은 사용자 결정으로 두지 않았다.
- 도보 전용 장소에는 순위와 시간대 표시가 없다.
- 히트맵은 행(구간)별 순위로 그린다. 혼잡도 분석 탭의 실제 평균 승하차 표시와 `/api/profile`은 제거했다.

## 검증 상태

검증 근거를 구분한다.

- **현재 코드에서 확인:** 위 구성과 API 계약, 순위 규칙·걷기 규칙(D-019 이전의 시간 막대·점수식 서술은 D-028로 대체됨), 22개 수동 역 좌표, 42개 선로 구간과 사용자 좌표에 맞춘 양 끝점은 소스와 자료를 읽어 확인했다. 현재 변경 후 `app.js` 문법 검사와 좌표·구간 끝점 일치 검사를 통과했다.
- **API 응답만 확인:** 이전 확인에서 `/api/stations`는 좌표 파일 변경 전 서버 프로세스가 보관한 값을 반환했다. 코드는 서버 시작 시 `STATIONS`를 읽으므로 재시작이 필요하다. 과거 결정 D-019에는 시간 막대 값과 독립 API 응답의 일치 확인이 기록돼 있다. 이 응답 확인은 브라우저 화면 확인을 뜻하지 않는다.
- **브라우저 확인 기록:** D-015~D-020에 핀·카드 위치, 출발지 변경, 분할선, 시간 막대, 결과 탭 등의 브라우저 확인이 기록돼 있다. 이는 그 당시 변경에 대한 기록이다.
- **아직 눈으로 확인하지 않음:** 사용자 제공 좌표로 조정한 선로 곡선, D-028 개편(순위 표시, 행별 순위 히트맵, 출발 시각 목록, 제거한 CSS로 인한 레이아웃 변화)은 현재 브라우저에서 시각 확인하지 않았다(사용자 확인 예정). 터치 기기·모바일 최종 확인과 역사 실제 위치·선로 중심선의 현장 정합도 확인하지 않았다.

## 모델 소개 탭 설명 개편 (2026-11-23, D-029)

모델 소개는 방문자가 저장소 문서를 읽지 않아도 이해하도록 쉬운 설명을 먼저 제공하고, 개발 과정·수치·용어의 기술 설명은 선택해서 펼쳐 보게 한다. 화면의 문장별 E-/D- 식별자와 문서 경로 참조는 제거한다. 용어는 키보드와 터치로 확인할 수 있게 하며, 짧은 표 항목은 한 줄로 유지하고 좁은 화면에서는 표 안에서 가로 스크롤한다.

OD는 학습용 추정값 생성, HGB는 그 값을 학습한 서비스 예측으로 설명한다. 이전 배분 방식 대 OD의 비교와 OD 직접 계산 대 HGB 예측의 평가를 구분한다. 학습용 추정값과 항저우 비교 기준을 독립 실측 정답으로 표현하지 않으며, 대전 피크 18건의 제한과 한산한 시간 미검증을 함께 밝힌다. 변경 후 검증 범위는 ROADMAP 완료 기록을 참고한다.

확인: 모델 소개 탭을 Chrome 헤드리스에서 1440/768/375/320px로 검사해 짧은 셀 줄바꿈·페이지 가로 넘침·깨진 내부 링크·중복 ID가 없었다. Enter/Space 펼침·접기와 용어 링크의 자동 펼침·초점·해시 이동을 확인하고 첫 화면 및 표 4 스크린샷을 검토했다. 외부 요청을 차단한 로컬 파일 검사이므로 지도·API·외부 폰트·다른 탭 전체의 시각 검증을 뜻하지 않는다.

## 실행과 남은 한계

프로젝트 루트에서 `.venv/Scripts/python.exe prediction_api.py --port 5500`으로 실행한다. 이미 5500 서버가 있으면 중복으로 시작하지 않는다. 코드 수정 후 정적 페이지는 새로고침하고, 서버 코드나 앱의 역 좌표를 수정한 경우에는 서버 프로세스도 재시작한다.

현재 구성은 로컬 실행용이다. 공개 배포 설정, 장소 운영시간·실제 도보 네트워크, 추천 순위의 실제 효용 검증, 실제 방문객 혼잡도 예측은 구현·검증 범위에 포함되지 않는다. 다른 API 설계 예시인 `/api/forecast/profile`은 구현되어 있지 않다.
