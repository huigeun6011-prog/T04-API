# 재차인원 추정 라벨과 예측 모델의 방법론

기준2026-11-23(이 문서의 본문 대부분은 2026-11-16 작성). 현재production·후보·실험을 구분한다. 확정요구·정확한파일/hash·남은문제는 [HANDOFF](../HANDOFF.md)가 정본이다.

> **갱신 안내(2026-11-19 이후):** production은 2026-11-19에 **열차 단위 OD 라벨 61일 HGB**로 교체됐다([D-027](../DECISIONS.md), [E-39](../EXPERIMENTS.md), [HANDOFF §4](../HANDOFF.md)). 아래 "두 단계가 다르다"와 "production과 현재생성코드의 차이", "HGB학습과 평가"의 production 설명은 **교체 전 production(Adam 라벨 731일)** 기준이며 이력으로 남긴다. 현재 production의 라벨 생성은 `make_od_labels.py`·`gt_train_od.py`이고 단계 구분은 [MODEL](MODEL.md)을 따른다. 마지막 절의 권고안은 실행·채택되었다.

## 두 단계가 다르다

1. `generate_ground_truth.py`는 역·시간별 무방향 승하차 집계와 열차 시간표로 상/하행 분배율p/q를 수치최적화한다. PyTorch Adam을 사용하지만 이 단계가 현재 미래예측 신경망이라는 뜻은 아니다.
2. `train_predict_model.py`는 추정 재차인원 라벨을 HistGradientBoostingRegressor(HGB)에 학습한다. `.joblib`이 실제 API의 예측모델이다. 이전PyTorch `best_model.pt`는 별도과거경로다.

전체열차의 실측정답이나 개별승객OD가 없다. 실제피크20사례중19매칭자료는 사후비교용이며 학습/튜닝에 쓰지 않는다. 이 자료의 출발전/후 측정정의는 공식확인되지 않았고 출발후로 작업한다는 사용자합의가 있다.

## 자료와 운행일

- 운행일D의05~23시와D+1의00시 승하차를연결한다.01~04시는정제시제외되며24시에합쳐지지않는다.
- 24시날씨도D+1일00시를쓴다.날씨는GT최적화이후HGB피처로붙인다.
- 학습서비스일2024-11-01~2026-11-01,731일·3,733,691행.마지막실제버킷은2026-11-02 00시다.
- 시간표는2026-03-30이후평일에20260330표,그외20250930표를쓴다.이후휴일은이전휴일표폴백이다.
- 공식엑셀→개편CSV→기존변환기→날짜JSON이라는경로와제작자의날짜명변경을확인했다.두버전재생성JSON460/242열차가각각기존과전체일치했다.
- `station_hourly_*.json`은이전모델/분석용파생자료다.현재GT는열차별시간표에서방향별배분가능정차수를직접센다.

## 분배 가정과 제약

각중간20역×20시간에p(상행승차비율),q(상행하차비율)를두어하루800개logit를최적화한다.반대방향몫은1−p/1−q다.중간역초기지리prior는p=s/21,q=1−s/21이며실제통행방향을측정한값이아니다.

과거실패에서기각한것은 **상하행을구분하지않은일괄균등배분**이다.기본방법은방향몫을추정한뒤 **같은역·시간·방향내열차끼리균등분배**하는가정을여전히유지한다.균등가정을모두폐기했다고설명하면틀린다.

- 출발승차전인원0,출발정차하차0,종착정차승차0은구조로고정한다.
- 종점잔여0과원시재차비음수는제곱 **soft penalty**다.최적화가정확히만족한다고보장하지않는다.
- 기본손실은열차별종점원시누적제곱평균 + 음수원시누적제곱평균 +2×지리prior손실이다.
- 현재개선코드는배분가능한방향만정규화한다.양방향모두불가능한관측은원본을수정하지않고slack으로남긴다.
- Adam학습률0.1,최대1000회,최저손실iterate복원·정체중단옵션이다.200/500/1000진단에서반복증가로손실은줄었지만물리위반이없어지지는않았다.

하드제약LP/QP나딥러닝대안이열등하다는공정비교실험을한것은아니다.현재선택은보유집계자료와시간표를연결하는가설적baseline이다.최적성·실제정확도·물리정답복원을완료했다고주장하지않는다.

## 세 가정의 선택 옵션과 검증

시간Huber soft정규화,과거동요일partial pooling,승차headway를각각구현했다.월~일7그룹/공휴일별도/시간표버전을구분하고과거112일만template에쓴다.평가일·미래일은제외하며confidence로부분공유한다.변수800개/일은그대로남는다.

headway는실제대기시간관측이아닌시간내균등입장가정이다.직전출발~이번출발구간을원본입장시간버킷과교차해다음시간열차에도배분한다.첫차경계05시,자정연속축,마지막출발이후입장가정량slack,source-hour기록을명시한다.하차는같은가정으로바꾸지않았다.

같은6일·5방법·2초기값·1000회로60run비교했다.정상5일평균종점MSE는기본539.62/시간541.72/요일541.91/headway1107.80/전부1147.53이다.부드러움/패턴일치는개선했지만전부적용이전반적인물리잔차개선은아니다.옵션을기본활성화하거나전체all모델로교체하지않았다. [실험 정본](../../outputs/diagnostics/assumption_ablation/report.md)을참고한다.

## HGB학습과 평가

피처는station_idx,hour,dir_code,is_weekend,temp,precip,snow,plan_version이다.범주형인덱스는역/방향/휴일여부/시간표버전이다.현모델에는월~일피처가없으므로요일모델채택시API까지변경해야한다.제곱오차를사용하고300iter,learning_rate0.08,max_leaf_nodes31,min_samples_leaf20,random_state42,early_stopping=False이다.

날짜순앞80%(584일,2026-06-07까지)학습/뒤20%(147일,2026-06-08~11-01)검증이다.평가후배포파일은전체기간으로refit한다.검증모델과배포모델의학습범위를혼동하지않는다.

production 추정라벨holdout MAE20.14/RMSE29.41/R²0.8766,별도후보는MAE21.94/R²0.8593이다.라벨정의가달라단순우열비교할수없다.실제피크19건은productionMAE375.99명/후보374.45명으로큰괴리가남았다.미매칭1건은사용자지시로비교에서무시했다.정확도·추천순위검증완료로해석하지않는다.

최근제안된smooth+pooling두개만의조합과가중치탐색은미실험이다.축제/비정규날짜제외도미실행이다.실험/재학습은사용자지시가있을때만한다.2026-11-16에격차진단([feasibility_bound](../../outputs/diagnostics/feasibility_bound/report.md))과대기열·정원모델실험(폐기권고)을마쳤고방향prior실험은 효과없음으로 폐기했다(E-14).진행상황과완료기록은[ROADMAP](../../ROADMAP.md)이정본이다.


## 권고하는 재차인원 역산 방식 (2026-11-17, 시도 E-01~E-19 기준)

시도별 상세와 수치는 [EXPERIMENTS](../EXPERIMENTS.md)가 정본이다. 이 절은 그 결과에서 도출한 권고안이다(작성 당시 문구는 아래). **2026-11-19에 61일 표본 라벨로 production에 적용됐다**([D-027](../DECISIONS.md)). 아래 '실행 게이트'의 전체 731일 재생성은 E-38에서 불필요하다고 확인됐다. 원문: *아직 production에 적용하지 않았고 실행 승인도 받지 않았다.*

### 권고: 열차 단위 OD 변수 + 균일 기준 정규화 (E-16, λ=0.01) 라벨로 HGB 재학습, 단 게이트를 통과한 뒤에만 교체

```
변수  x[k,a,b] ≥ 0   열차 k가 정차 a에서 타서 b에서 내린 인원 (같은 열차에서 a가 b보다 앞)
재차  L(k,i) = Σ_{a≤i<b} x[k,a,b]          → 보존식, 종점 0, 비음수가 구조로 성립
목적  min Σ_칸 (적합−관측)² / (관측+10)  +  λ · Σ ( x·log(x/q) − x + q )      λ = 0.01
기준  q = 각 승차 칸의 관측 승차 인원 B(역,시간)를 그 칸의 열차에 똑같이, 이후 정차역에 똑같이 나눈 값
```

- **채택 이유:** (1) 물리 위반이 기존 2.8%에서 0이 되고 clamp·종점 0 덮어쓰기·soft penalty가 필요 없다. (2) 피크 19건 사후 비교에서 추정/실제가 0.51 → 0.62, MAE 325 → 254로 처음 개선됐고 headway 때와 같은 부하 붕괴가 없다. (3) 기존 방식과 순위 패턴이 비슷해(Spearman 0.94) 추천 순위의 연속성이 있다. (4) 가정이 적고 명시적이다(균일 기준 + 시간별 합계).
- **무엇을 주장하지 않는가:** 열차별 편차는 시간별 합계로 식별되지 않는다(LP 범위 0 ~ 약 6,000명, E-17). 이 라벨은 "균일 OD 가정 아래의 평균 열차" 수준이고, 피크 열차 대비 약 0.6배라는 수준 격차가 남는다. 이동 거리 prior가 수준을 정한다(균일 0.62, 중력 감쇠 0.37~0.54).
- **쓰지 않는 방식(효과 없음 또는 악화):** headway와 정원·대기열(E-13, E-15), 자료 기반 방향 prior(E-14), 연속 도착률 곡선(E-15), 열차마다 자유 계수와 목적지 분포의 동시 추정(E-18, E-19). 중력 감쇠 기준은 수준을 낮춘다(E-16).
- **보류한 선택 요소:** 저차원 시간대 계수 + 여러 날 합치기(E-19). 목적지 분포를 밖에서 고정하고 평일마다 같은 열차가 같은 계수를 갖는다는 미검증 가정이 필요하며, 얻는 것은 시간별 합계에 이미 보이는 부드러운 흐름이다.

### 실행 게이트 (각 단계는 사용자 승인 후 진행)

1. **추천 민감도 시험(저비용):** 평일·휴일 표본 약 60일에서 OD 라벨을 만들고(프로세스 4개 이하, 낮은 우선순위로 약 1시간 안팎), 같은 피처로 HGB를 학습한 뒤 기존 production 모델과 같은 추천 질의(출발지 여러 곳 × 시간 범위)로 상위 10곳 겹침과 순위 상관을 비교한다. 라벨 정의가 달라 MAE는 직접 비교하지 않는다. 겹침이 높으면 교체 이득은 주로 물리 일관성과 수준이다.
2. **전체 재생성(고비용):** 731일 × 하루 70~330초(단일 프로세스 약 14~67시간, 병렬 4개로 약 4~17시간)이므로 밤사이 백그라운드로 돌리고 설정(λ, 허용 오차)과 시드, 원본 해시를 저장한다. 계산 비용을 줄이는 방법(표본 일수, 풀이 허용 오차 완화)은 먼저 검증한다.
3. **교체:** 기존 모델·CSV 백업과 SHA256 기록 후, 날짜 holdout·보존식·종점 감사·피크 19건 사후 보고(1회, 튜닝 금지)를 거쳐 `outputs/load_predictor.joblib`을 교체한다. 낮은 내부 loss나 추정 라벨 MAE만으로 교체를 선언하지 않는다.
4. **화면:** 재차인원을 사람 수가 아니라 상대 혼잡도로 읽도록 안내한다(한계 문구는 이미 혼잡도 분석 탭에 있다).

실행 절차, 필요 파일, 소요 시간, 사용자에게 보고하고 멈출 지점은 [LOAD_ESTIMATION_RUNBOOK](LOAD_ESTIMATION_RUNBOOK.md)에 있다.

### 남는 한계

- 합계 불일치가 0.6~2.4% 남는다(소프트 제약). 열차 하나의 재차는 자료만으로는 식별되지 않으므로 어떤 값도 가정이 정한다.
- 승하차 합계가 곧 실제 승객이라는 가정, 한 열차만 탄다는 가정(환승·연결 없음), 재차인원이 출발 후 값이라는 작업가정은 검증하지 않았다.
