# 작업 지시서: 항저우 지하철 태그 데이터에서 열차 도착시각(시간표) 복원

**진행 상태: 보류 (2026-11-18, 사용자 결정, [D-022](../DECISIONS.md)).** C선 1/08 하루에서 피크 연결 방식은 조각화 관문에서 실패했고(E-22), shift-and-stack 방식도 양끝 2역 이내 45.33%로 기준 60%에 못 미쳤다(E-23, 보고서 기준). 1/15 독립 검증 등 추가 작업은 보류하고, 열차 단위 공식 시간표와 개인별 태그(또는 열차별 재차 실측)를 가진 공개 자료를 조사한다. 폐기가 아니라 보류이며 조사가 실패하면 재개할 수 있다. 이 문서의 나머지는 보류 전 작업 지침이다.

**후속 갱신(2026-11-18):** 사용자 결정으로 C선만 보고 1/01~25 전부 사용, 과적합 허용, 평일·주말 별도 풀링한다(날짜 고정 철회, D-021). 열차는 계획보다 늦게 올 수는 있어도 일찍 오지 않는다. 궁극 목표는 시간표가 아니라 해당 일자 모든 열차의 출발점·종점·정차역(단축·회차 포함)이며 지금은 전 구간 운행 가정 시간표만 있어 미달성이다. 후속 실험 E-24~E-27(환승 제외 검증, 날짜 풀링 + 랙, pool2 수정, 단축·회차 진단)은 [EXPERIMENTS](../EXPERIMENTS.md)에 있고, pool3(E-28, 최종 시간표 후보로 채택)와 양성 대조(E-29, 현재 단축 진단 규칙은 심은 단축을 찾지 못함)까지 기록했고, 새 종합 규칙 재양성 대조(E-30: 평일 혼잡시간대 25% 이상 단축 검출, 가짜 지원 0)와 평일 최종 시간표 후보·분석 구간(E-31, `outputs/hangzhou/lineC_final/`, 05~07시는 low_signal·미확인)까지 기록했다. 반박 칸 검출 시험(E-32: f=25% 이상 단축은 모든 시간대에서 검출, 시험한 반박 칸 12→37)과 주말 최종 시간표(E-33: 491열차, 단축 진단 없음)까지 기록했다. 정답 재차인원·OD 역산 시험은 방향 메모만 작성했고(미실행) 별도 에이전트·사용자 승인을 기다린다: [HANGZHOU_OD_TEST_BRIEF](HANGZHOU_OD_TEST_BRIEF.md). 목표(모든 열차의 출발점·종점·정차역)는 평일 전 구간 운행 가정과 모순 없는 후보까지이며 열차 한 대 단위 판정·공식 시간표 비교는 미확보다. 위 "보류" 문구는 이 갱신으로 항저우 작업이 계속 진행 중임을 반영해 다시 읽는다: 1/15 독립 검증은 보류이나 C선 풀링 시간표 개선은 계속하고 있다.

## 1. 목적 (왜 하는가)

사용자는 "역·시간대별 승차/하차 합계 + 열차 시간표 → 열차별 재차인원 역산"을 연구 중이다.
이미 완전 합성 데이터로 검증했으나, 합성 데이터에서는 기존(설계된) 방법론이 유리하게 나왔고,
OD를 추정·복원하는 방법이 특별히 강점을 보인 부분이 있었다.
이 방법이 실제로 효과가 있는지 보려면 **실제 태그 + 실제 시간표**가 필요하다.

문제: 항저우 데이터에는 시간표가 없다. 실제 태그에 합성 시간표를 얹으면 의미가 없다(사용자가 명시적으로 거절함).
그래서 **태그 자체에서 열차 도착시각을 복원**한다. 필요한 산출물은
"어느 열차가 언제 어느 역에 도착했는가" (열차 ID, 역, 도착시각, 방향).

## 3. 이미 확인한 사실 (예비 분석, 거칠다)

- 이용객이 적거나 중간인 역(예: C/60, A/74, B/32)에서는 열차 도착 때마다 약 1분 안에 **출장 태그가 몰리는 피크**가 뚜렷하다.
  피크 간 간격 중앙값이 대략 4~8분(양방향이 섞인 값).
- 가장 붐비는 역(B/15, 하루 출장 15만 건)은 출장이 끊기지 않고 이어져서 단순 피크 검출이 실패했다(피크 0개).
  혼잡 역은 별도 처리가 필요하다(게이트별 분리, 방향별 분리, 입장 태그와의 연계 등).
- 검출은 `gaussian_filter1d(sigma=10s)` + `find_peaks(height=mean*2.5, distance=45s)` 정도의 거친 방법이었고, 방향 분리는 하지 않았다.
  수치는 확정값이 아니다.

## 4. 해야 할 일 (순서대로)

### 4-1. 데이터 준비
- pandas로 읽고(`parse_dates=['time']`), 출장(status=0)과 입장(status=1)을 분리한다.
- 일 단위로 `(lineID, stationID)`별 1초 단위 히스토그램을 만든다. 용량이 크니 필요한 열만 읽고 `category`/정수형을 쓴다.
- 파이썬 실행은 `python3 -I`로, 작업 스크립트는 데이터 폴더(`data/external/hangzhou/`)와 다른 디렉터리(`scripts/hangzhou/`)에 둔다.

### 4-2. 역 순서와 방향 정하기
- `Metro_roadMap.csv`가 있으면 그것을 쓴다. 없으면 아래 가설을 데이터로 검증한다.
- **가설(참고용, 확정 아님): `stationID` 번호가 노선을 따른 순서다.** 2019-01-08 예비 확인(2026-11-18): 번호가 노선별로 연속 구간이고(B 0~33, C 34~66 중 54번 없음, A 67~80), 같은 사람의 같은 노선 입장→출장 쌍(약 74만 개)에서 번호 차이가 1 늘 때 소요시간 중앙값이 약 2.5분씩 늘고 순위 상관이 0.93~0.96이다. 평균 경향이므로 **모든 인접 번호 쌍이 실제 인접 역이라는 보장은 없다.**
- 번호를 순서로 단정하지 않는다. 인접 번호 쌍마다 (입장→출장) 소요시간 하위 분위수를 구해 이상치(너무 길거나 짧은 구간)를 찾고, 번호 순서와 어긋나는 역 쌍을 표시한다. 번호 순서를 채택한 곳과 데이터로 바꾼 곳을 구분해 기록한다.
- **분기(Y자)가 있을 가능성이 크다(알려진 구조 추정). 어렵다는 점을 알고 있으므로 분기를 확정하려고 시간을 쓰지 않는다.** 번호 순서에서 구간 시간이 비정상인 역 쌍, 번호가 연속인데 서로 도달하는 소요시간이 이상한 역 쌍이 나오면 분기 후보로 표시만 하고, 그 노선은 "순서 불확실"로 신뢰도를 낮춘다. 분기 여부를 모르는 채로 진행할 수 있는 단계(피크 검출)까지만 한다.
- 같은 사용자·같은 노선에서 입장 직후 3시간 이내 출장을 쌍으로 묶어 방향(상/하행)을 정한다. 출장 태그마다 "어느 방향 열차에서 내렸는가"를 이 쌍으로 라벨링하면 양방향이 섞인 피크를 분리할 수 있다.
- 환승(노선 간 이동)은 입장 태그가 없는 환승 구간이 있을 수 있다(환승 시 별도 태그가 있는지 확인할 것). 확인 전에는 단일 노선 내 이동만 쓴다.

### 4-3. 역·방향별 도착 피크 검출
- 방향별 출장 태그의 시간 히스토그램에서 피크를 검출한다.
  피크의 폭(약 30~90초)과 간격이 합리적이어야 한다. 피크 높이는 역별 정규화.
- 혼잡 역(연속 흐름)은 게이트(`deviceID`)별로 나눠 피크를 합치거나, 피크 대신 변화점 검출/디컨볼루션을 시도한다.
- 각 피크의 "대표 도착시각"은 피크 시작 직전 쪽(가장 이른 출장 태그 쪽)에 가깝게 잡는다
  (승객은 내려서 게이트까지 걷는 시간이 있으므로 도착시각 ≤ 첫 태그 시각).
  역별 하차→태그 지연(걷는 시간)은 역·게이트 구조에 따라 다르며 불확실성으로 기록한다.

### 4-4. 열차 궤적으로 묶기
- 역 간 운행시간을 추정한다: 같은 사용자의 (입장 시각, 출장 시각) 쌍에서 (출장−입장)의 하위 분위수(예: 10~20%)가
  "대기 거의 없음 + 주행 + 걷기"에 가까운 값이다. 역 쌍 (i, j)별로 구해 역 간 구간 운행시간으로 분해한다.
- 같은 방향의 연속 역들의 피크를 운행시간 제약으로 연결해 열차 궤적(열차 ID = 궤적)을 만든다.
  - 제약: 같은 열차가 역 i에 도착한 뒤 역 i+1에 도착하기까지의 시간 = 구간 운행시간 + 정차시간 ± 오차.
  - 추천 방식: 방향별로 시간 순서 매칭(헝가리안 또는 DP). 열차 추월은 없다고 가정(순서 보존).
  - 누락 피크(승객이 적어 검출 안 됨)는 간격 규칙성으로 보간하고, 보간한 항목은 `imputed=True`로 표시한다.
- 출력: `train_id, direction, stationID, arrival_time, imputed, peak_strength`.

### 4-5. 평가 (정답이 없으므로 일관성으로 평가)
정답 시간표가 없으니 "맞췄다"고 하지 말고 아래 지표를 보고한다.
1. 복원한 열차 수(노선·방향별) vs. 공식 정보(2018-10 기준 편성: 1호선 52, 2호선 46, 4호선 29편성이 공식 보도에 있음.
   A/B/C와의 대응이 불명이므로 참고만).
2. 열차 간 간격(헤드웨이) 분포가 시간대별로 합리적인가(비혼잡 시간 일정, 피크 시간 짧음).
3. 설명 비율: 출장 태그 중 복원한 열차 도착에 귀속되는 비율.
4. 입장→출장 쌍을 복원 열차에 배정했을 때, 재차인원이 음수가 되지 않고 종점에서 0으로 수렴하는가.
5. 일부 역의 피크를 숨기고(홀드아웃) 보간이 숨긴 값을 복원하는지.
6. **열차가 노선을 이어서 달리는가(조각난 열차 비율).** 복원한 열차 중 (가) 종점에서 종점까지(분기 구조는 분기 끝까지) 이어진 열차의 비율, (나) 지나는 역 수의 분포와 구간 하나·둘만 가는 열차의 비율, (다) 시작 역과 끝 역의 분포(종점·소수 역에 몰리는지, 아무 역에서나 시작하고 끝나는지)를 센다. **검출한 피크만으로 이은 열차와 보간을 포함한 열차를 따로** 계산한다. 조각난 열차는 실제 회차·입고일 수도 있지만 승객이 적은 역에서 피크를 놓친 복원 실패일 가능성이 더 크므로, 많으면 복원 실패로 읽는다. 기준값(예: 전 구간 열차 비율, 한 구간 열차 비율의 상한)은 A단계에서 노선별 피크 검출률을 본 뒤 **복원을 돌리기 전에** 이 문서에 적어 고정하고, 결과를 본 뒤 바꾸지 않는다.

### 4-6. 한계를 명시
- 도착시각 추정에 하차 지연(걷는 시간)과 운행시간 가정이 들어가므로, 이 복원 시간표를 쓰는 이후 OD 복원 평가는 **부분적으로 순환적**이다.
  결과를 "독립 정답과의 비교"로 서술하지 말고 "일관성 검증"으로 서술한다.
- 혼잡 역은 복원 불확실성이 크다. 이 역들의 신뢰도를 표시한다.

## 6. 작업 방식

- 한국어로 보고한다. 코드·변수명은 영어.
- 사용자에게 문의·요청·연락을 시키지 않는다. 필요한 파일이 없으면 무엇이 없는지만 짧게 알린다.
- 확인하지 못한 것은 "확인하지 못했다"고 쓴다. 노선 A/B/C가 1·2·4호선 중 무엇인지, 데이터 라이선스 등은 확정하지 않는다.
- 결과 요약은 먼저 결론(복원 가능 여부, 신뢰도 높은 역/낮은 역), 그다음 근거 순서로 쓴다.

## 7. C선만 진행: 노선 식별 추정과 단계 관문 (2026-11-18, 사용자 결정)

- 범위: **C선만** 복원한다. 실패하면 멈추고 사용자에게 돌아간다. 모든 산출물과 코드에는 A/B/C라고만 쓴다(하드코딩 금지).

- 관문(2026-11-18 당시 실행 전 설정, 결과를 본 뒤 바꾸지 않기로 했었다. 사용자가 이후 고정 불필요로 정함(분석 일자·규칙 고정은 필수가 아니며 필요하면 바꿔도 된다. 이미 낸 1/08 결과는 사실로 유지)):
  - 1단계(고정 환승역): 허브 (B10,C51), (A77,C46)로 교차노선 통행을 평가. B-C ±5분 이내 비율 ≥ 60%이고 B0의 단일 허브(C48) 비율(59.9%)보다 3%p 넘게 나쁘지 않을 것, A-C ±5분 이내 ≥ 80%.
  - 2단계(C선 닫힌 계): 허브에서 교차노선 통행을 C 구간으로 분리해 C 승하차를 보강. C 하차 중 보강(가상) 비율 보고, > 60%이면 중단.
  - 3단계(순서·방향): C 역 ID 순서 검증(인접쌍 분위수 이상치), 방향 라벨(구간 입·출장 위치 차이의 부호). C 하차의 ≥ 60%가 방향 라벨을 가질 것.
  - 4단계(역·방향 도착 피크): stageA_peaks.py의 clear/weak/none 정의를 그대로 사용. 실제 하차만으로 계산한 (역,방향) 중 clear인 칸이 10~16시 C 하차의 ≥ 60%를 덮을 것(가상 하차 포함 결과도 보고).
  - D단계(열차 궤적): 방향별 피크(롤링 높이 규칙 height=2.5×±30분 평균), 구간 운행시간은 01-08 동선 통행에서 구간별 중앙값으로 보정(두 단계: ±120초 넓은 창 → ±45초), 헝가리안 매칭, 연속 결측 최대 2역까지 보간(imputed=True). 단편화: 검출 피크만으로 만든 열차 중 단점-단점 운행(출발 터미널에서 2역 이내 첫 검출, 도착 터미널에서 2역 이내 마지막 검출) 비율 ≥ 60%, 검출 역이 2개 이하인 열차 ≤ 5%. 보간 포함 수치도 보고.
