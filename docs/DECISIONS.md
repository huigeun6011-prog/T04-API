## D-001: 지하철 01 ~ 04시 기록 처리법

- 결정: 완전 무시.
- 근거
  -- 1. 01 ~ 04시에 테스트 목적의 기록이 남거나, 역사 직원의 출퇴근으로 기록이 남는 경우가 있을 수 있음을 확인함.
  -- 2. 역사 운영시간과 열차 운행시각표를 고려했을 때, 해당 시점에 기록이 남을 수 없음.
- 결과: API로 추출한 ./data/raw/subway 데이터를 ./data/processed/subway 데이터로 정제할 때, 01 ~ 04시 기록을 제거함.
- 한계: 01 ~ 04시 기록의 출저에 대한 공식 입장을 확인하지 못한 임의판단임.

## D-002: 지하철 00시 승하차 기록 처리법

- 결정: 전일 열차 운행기록으로 처리.
- 근거
  -- 1. 정황상 00시는 해당 일의 시작시점이므로, 운행일로 고려하면 어제의 것에 해당됨.
  -- 2. 03시에 추출한 API 데이터 기준, 전날의 00 ~ 16시 데이터까지만 존재했으며, 17 ~ 23시 기록은 아직 갱신되지 않아 0으로 확인되었음.
- 결과: ./data/processed/subway 내 운행일 데이터 활용 시 당일 05 ~ 23시 데이터와 익일 00시 데이터를 참고함.
- 한계: API 데이터가 운행일을 기준으로 했을 가능성이 존재함. 명시되지 않아 판단 불가능.

## D-003: 시간대별 운영하는 지하철 수 계산법

- 결정: 열차 시각표를 바탕으로 각 열차의 운행 계획을 추측, 시간대별로 분류.
- 근거
  -- 1. 물리적으로, 두 대 이상의 대전 지하철은 같은 방향으로 동시에 운행될 수 없음.
  -- 2. 시계열 순으로 판단하였을 때, (n)번째 역에서 (x)분에 출발한 열차와 (n+1)번째 역에서 (x+k)분에 출발한 열차는, 정황상 동일한 열차라고 판단할 수 있음. (단, 1 ≤ k ≤ 4)
  -- 3. 열차별 계획된 운행시간을 추출해냈으니, 이를 바탕으로 한 시간 구간으로 운행되고있는 열차의 수를 계산할 수 있음.
- 결과
  -- 1. 열차별로 몇 시에 어느 역에 정차하는지 계산됨.
  -- 2. 시각 별로 운행되는 열차의 수와 방향이 계산됨.
- 한계
  -- 1. 기존 열차들의 역간 시간을 바탕으로, 종착역 도착 시간은 예측시간으로 계산됨. (종착역은 열차 시각표에 표시되지 않음)
  -- 2. 시각표를 바탕으로 역산된 결과임.
