## 범주별 점검 결과

1. D-028 준수: 웹 소스(app.js, analysis.js, index.html)와 `recommend()` 실제 응답에서 `mean_load`, `max_load`, `score`, `quiet`, `predicted`를 찾았으나 없다(`json.dumps` 전체 검색으로 확인). `departure_time`은 `hour_ranks[].trains`에만 있다. `quiet_weight`, 슬라이더, 실제 평균 승하차, `/api/profile`, `matrix`는 코드에서 제거됨. 히트맵 순위는 장소(행)별이며 행 사이 비교 없음. 장소 목록 정렬은 `(distance_km, name, rank, hour)`로 혼잡도 사용 없음(rank는 같은 장소 안 대표 선택에만 쓰임). 위반 의심은 R-001, R-002, R-008. 가시 문구와 aria 텍스트에 사람 수 없음.
2. API 순위 로직: `plain_ranks` 정렬 키 `(값, 시간)`으로 이른 시간 우선 확인. `route_ranks`는 필터 전에 전체 창에서 계산됨(확인). 시간 평균은 열차별 구간 평균의 평균이며 근/원 그룹 나누기와 도보 한도 상한(`limit//3`)은 순위 뒤에 적용됨. 도보 전용은 `rank=None, rank_n=0, hour_ranks=[]`. `HIDDEN` 필드는 응답에서 실제로 제거됨. `/api/predict`와 CLI `predict_load.py`(`--help` 실행 확인)는 변경 전과 같다(CLI 예측 자체는 실행하지 않음). 문제: R-003, R-006, R-011.
3. 프런트엔드: `rank_n == 1`일 때 `Math.max(1, rank_n - 1)`로 0 나눗셈은 방지됨. 순위 공백은 시간 루프로 그려져 깨지지 않으나 강조 표시가 잘못될 수 있음(R-003). `escapeHtml`은 따옴표까지 이스케이프하며 POI 이름은 모두 이스케이프됨. 이스케이프되지 않은 값은 서버 숫자(`rank`, `hour`)뿐이라 XSS 경로는 찾지 못함. 키보드: 시간 막대는 `<button>`이고 `aria-pressed`와 순위 문장(숫자는 정수 순위뿐)을 가짐. 재검색 뒤 상태: R-004, R-009, R-010. `node --check`로 app.js, analysis.js 문법 통과. 제거한 CSS 클래스가 index.html/JS에서 쓰이는지 확인했고 사용처 없음.
