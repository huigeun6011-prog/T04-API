# 세 가정의 구현과 원인별 검증

## 실행한 비교

실제 피크 재차인원 CSV는 읽지 않았다. 기본 배분, 시간 정규화만, 동요일 pooling만, 승차 headway만, 세 가정 전부의 5종을 같은 6운행일·2초기값·1000 Adam회로 비교했다. 총60회, solver 실험 약115초다. 초기값은 기존 지리 prior와 logit에 표준편차0.25 잡음을 준 seed11이다. 1000회라는 연산 예산을 맞추기 위해 이번 비교의 조기 종료는 비활성화했다.

최적화 변수는 모든 방법에서 하루800개(p/q 각각20중간역×20시간)로 같고,731일을 독립 처리하면584,800개다. pooling은 고정 과거template로 일별비율을 부분공유하는 방식이며 일별 변수 자체를 없애지 않는다. 일자별1000회 중앙 실행시간은 기본1.67초,시간정규화1.98초,pooling1.85초,headway1.69초,전부2.25초였다. 초기값2종의 원시 terminal+negative loss 차이는 최대 기본0.143%,시간정규화0.153%,pooling0.119%,headway0.108%,전부0.089%다. 두 초기값만 비교한 제한적 안정성 검사다.

대표일은 개편 전 평일/토요일, 개편 후 과거 동요일 이력이 있는 평일/토요일, 일반 평일, 앞선 원본 총량 감사에서 발견한 자정 이상 가능일이다. 특정 실제 피크 인원에 맞춰 고르거나 조정하지 않았다.

## 각 가정의 의미와 구현

1. 인접시간 p/q 차이에 Huber soft penalty를 적용했다. Huber delta=0.15, 가중치1000을 미리 고정했다. 큰 출퇴근 변화도 허용하며, 같은 비율로 강제하지 않는다. 양방향 분배가 식별 가능한 관측 셀만 정규화한다.
2. 월~일 7종을 분리하고, 명시된 공휴일을 8번째 별도 그룹으로 둔다. 평일/휴일 binary를 요일로 대신하지 않는다. 시간표 개편 전후도 분리한다. 과거112일의 같은 그룹에서 얻은 독립 일자별 비율을 평균내고, 셀당2일 미만이면 사용하지 않는다. confidence=n/(n+4)를 곱한 soft pooling(가중치1000)이다. 하루 비율을 공통값으로 고정하지 않는다.
3. 승차에만 uniform-within-hour arrival 가정을 적용한다. 해당 역·방향의 직전 출발~현재 출발 구간과 gate입장 시간 버킷의 겹치는 분량으로 승차를 배분한다. 실제 승객 대기시간을 관측한 값이 아니다. 하차 배분은 기존 방식이다.

### headway 경계

- 첫차 이전 출발시각은 관측할 수 없으므로 운행일05:00을 입장 시작 경계로 둔다.
- 05:59 입장자가06:02열차를 탈 수 있으므로 source gate hour와 train stop hour는 다를 수 있다. `boarding_sources`에 source 시간·배분량을 저장한다.
- 자정은 같은 운행일의24:xx 연속분 축으로 처리한다.
- 양방향 모두 마지막 출발을 지난 입장량은 이미 떠난 열차로 보내지 않고 explicit slack으로 남긴다.
- 한 방향만 운행 가능한 시간 조각에서는 그 방향으로 정규화하고, 같은 시각의 복수 출발은 노출량을 나눈다.

## 누수 방지

template 원자료는 앞서 독립 일자별로 계산한 후보 비율이다. 어떤 평가일도 template에 넣지 않으며, 평가일보다 이전 날짜만 선택한다. 이 실험의 평가6일 전체는 과거에 속하더라도 제외한다. 예를 들어2026-05-13의 template 최신일은2026-05-06이며 같은 수요일6개를 사용했다. 미래일·평가일의 비율을 임의로 바꿔도 snapshot이 바뀌지 않는 테스트를 통과했다.

전체 재생성 CLI에는 `--template-fit-through`를 추가했다. 고정 날짜 holdout을 시행한다면 마지막 학습일을 지정해서 검증기간 중 앞선 날짜도 template로 흘러들지 않게 할 수 있다. 시간창은 이 학습 종료일에서 고정된다.

## 결과

자정 이상 가능일을 따로 보고 정상5일 평균을 비교했다.

| 방법 | 원시 종점 MSE 평균 | 원시 음수 MSE 평균 | 인접 비율 변화량 | 동요일 template MSE |
|---|---:|---:|---:|---:|
| 기본 |539.62|12.14|0.1497|0.01163|
| 시간 정규화 |541.72|12.22|0.1104|0.02580|
| 동요일 pooling |541.91|12.14|0.1439|0.00636|
| 승차 headway |1107.80|54.01|0.2741|0.12638|
| 세 가정 전부 |1147.53|53.10|0.1809|0.05115|

시간 정규화는 비율의 인접 변화량을26.3% 줄였으며, pooling은 동요일 template와의 거리를45.3% 줄였다. 각 가정의 의도대로 작동하지만 이것만으로 실제 재차인원 정확도 개선을 의미하지 않는다. 시간 정규화/동요일 pooling의 원시 종점 MSE는 각각0.39%/0.42% 증가했다.

template 역시 승객 방향을 관측한 값이 아니라 기존 독립일자 최적화에서 나온 추정치의 평균이다. 같은 prior의 편향을 공유할 수 있다. 현재joblib 입력의 is_weekend(binary)는 월~금 차이를 표현하지 못하므로, 향후weekday 후보모델을 학습한다면 day_of_week와 공휴일 정보를 추가하고 API계약까지 함께 바꿔야 한다. 이번 검증에서는 모델입력을 바꾸지 않았다.

headway와 전부 적용은 평일3일에서 종점·음수 잔차가 커졌으며 토요일2일에서는 종점 MSE가 줄었다. 전부 적용 시 정상5일 평균 종점 MSE는 약2.13배, 음수 MSE는 약4.37배였다.

2025-08-14 자정 이상 가능일은 종점 MSE가44480.50에서 전부 적용2560.55로 감소했다. 그러나 승차 slack이98명에서4357.83명으로 늘어난다. 마지막 정규표 출발 후 관측된 입장량을 배분하지 않았기 때문에 극단 잔여가 작아지는 측면이 크다. 이를 예측 정확도 개선으로 해석하면 안 된다.

## 구현·자료 검증

- 첫차/시간경계/마지막차 처리와 다음시간 열차로 이전시간 입장자 연결 테스트 통과.
- 월~일과 명시공휴일 그룹 분리 테스트 통과.
- 미래와 평가일 template 값 변조 불변성, 학습종료일 cap 테스트 통과.
- 60회 전부 raw 보존식·명시 투영 관계·출발전0·학습load비음수 검사 통과.
- 전부 적용한2026-05-13 CLI 출력5281행/242열차를 실제 저장 후 재검증했다. source gate hour 기준440역시간셀에서 배분+slack=원본 검사를 통과했다(허용0.001명, 최대 설명불가오차 승차0.000133명/하차0.000076명).
- optimized daily 변수는 여전히800개다. pooling은 별도로 과거에서 추정한 공통목표로 수축시키는 방식이며, 일별 변수 수 자체를 줄이지 않는다.
- 대표일별 solver 시간은 기본 약1.6~1.7초, 시간 정규화 약2.0초, pooling약1.8초, headway약1.7초, 전부약2.3초였다. 최초 optimizer초기화는 별도 startup overhead를 포함한다.

## 판단과 산출물 상태

세 가정을 각각 켜고 끄는 로직과 전체 CLI는 구현했다. 그러나 전부 적용이 일반적인 물리 잔차 개선을 보이지 않아, 전체731일 전부 적용 재생성·재학습이나 production 교체는 진행하지 않았다. 실제 피크 사후검증도 이번 recipe를 배포 후보로 고르지 않았으므로 반복하지 않았다. 기존20실제사례에 맞춘 튜닝은 없었다.

수치 전체는 `results.json`, `results.csv`에, template 관측 배열은 `weekday_observations.npz`에 있다. 구성·seed·template source SHA256·평가일·날짜 cutoff를 남겼다.

재현 명령:

```powershell
.venv/Scripts/python.exe scripts/data_prep/experiment_gt_assumptions.py
```

선택 옵션을 켠 소규모 CLI:

```powershell
.venv/Scripts/python.exe scripts/data_prep/generate_ground_truth.py --start-date 2026-05-13 --end-date 2026-05-13 --output outputs/diagnostics/assumption_ablation/cli_all_one_day.csv --workers 1 --epochs 1000 --patience 0 --temporal-weight 1000 --pooling-weight 1000 --boarding-headway --template-bank outputs/diagnostics/assumption_ablation/weekday_observations.npz --template-fit-through 2026-05-12
```
